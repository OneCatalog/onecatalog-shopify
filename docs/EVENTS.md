# Точки расширения (§8) — поверхность интеграции на Shopify

В Shopify «сайтовый слой» — это **тема магазина и другие приложения**. OneCatalog Import
не форкается; расширение строится поверх данных, которые он пишет нативно и в metafields.

## Metafields (namespace `onecatalog`)

На каждый импортированный товар приложение пишет метаполя — это и есть стабильная
поверхность для темы/других приложений:

| Metafield | Когда | Назначение |
|---|---|---|
| `onecatalog.public_id` | всегда | бизнес-ключ OneCatalog (идемпотентность) |
| `onecatalog.spec_<slug>` | импорт характеристик | значения характеристик (текст) |
| `onecatalog.country` | если включён импорт страны | страна происхождения |
| `onecatalog.collection` | коллекции с target=metafield | список коллекций (через запятую) |

Нативно также заполняются: `vendor` (бренд), product `tags` (теги), images (медиа),
custom collections (категории/коллекции при target=collection), вариант `sku`
(артикул), `price`/`compareAtPrice` и инвентарь (B2B).

**Чтение в теме (Liquid):**
```liquid
{{ product.metafields.onecatalog.public_id }}
{{ product.metafields.onecatalog.country }}
```
Для фильтров/витрины метаполя можно вынести в Storefront через настройку видимости
metafields (Settings → Custom data → Products) или через app metafields definitions.

## B2B и change-detection (§13.4)

Синхронизация цен/остатков идёт по **scan-and-diff**: на товар пишется сигнатура
результата в `OneCatalogMeta` (внутренняя таблица приложения), и при следующем прогоне
обновляются **только изменившиеся** товары. Если строите свою раскладку по регионам/
складам, учитывайте: обновление триггерится изменением итоговой цены/скидки/остатка/
статуса (основной регион + сумма складов), а не каждым полем фида.

## Вебхуки

Приложение обрабатывает `app/uninstalled` (очистка сессий). Точки под будущее —
`products/update`, `app/scopes_update` — добавляются по мере необходимости.
